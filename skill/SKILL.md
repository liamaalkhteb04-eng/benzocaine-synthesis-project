# AI 유기합성 보고서 생성 스킬

## 기본 모드와 우선 규칙

기본 동작은 **전체 보고서 생성(full-report mode)**이다. 사용자가 물질 정보나 결과 폴더를 제공하면 아래 작업 흐름에 따라 물질을 확인하고, 실제 예측과 분석 근거를 정리한 뒤 Solar Pro 4가 보고서 본문 전체를 작성한다. 입력 자료가 이미 준비되어 있어도 모델 결과를 사실 확인 없이 복사하지 말고, 해당 실행 기록과 검증 파일을 대조한다.

**부분 수정(targeted-revision mode)**은 사용자가 특정 절·문장·표 셀만 수정해 달라고 명시한 경우에만 적용한다. 지정 범위와 결과 형식만 수정하며, 그 외 본문과 과거 대화의 작업 지시를 새 요청에 가져오지 않는다. 부분 수정 요청이 없으면 기존 요청·A/B 비교·문장 교체 지시를 프롬프트에 포함하지 않는다. 이 스킬 자체가 과거의 특정 수정이나 비교 작업을 요청하지 않는다.

Solar Pro 4가 과학적 본문을 작성한다. 표·그림 배치, 글꼴, 구조식 렌더링, 페이지 나눔 등 변환 문제는 코드에서 고친다. 저장된 Solar 응답을 문서로 다시 변환하는 작업은 새 Solar 호출로 기록하지 않는다. 모델 호출이나 프로그램 설치는 해당 작업에 대한 명시적 승인이 있을 때만 한다. API 키·토큰·인증 헤더는 출력하거나 보고서에 넣지 않는다.

## 전체 작업 흐름

### 1. 물질 입력 및 구조 확인

새 물질은 `inputs/input-template.json`을 복사한 `inputs/<target_id>.json`에 입력한다. `target_id`, 물질명, 한국어명, 의도한 화학형(중성체·염·이온 등), 이성질체 정보를 포함한 SMILES, 예상 분자식, PubChem CID 또는 검증 가능한 구조 출처를 채운다. 벤조카인 입력은 벤조카인 예시로만 사용한다.

입력 물질명과 구조가 일치하는지 RDKit·신뢰 가능한 식별 출처·프로젝트 검증 기록으로 확인한다. 수소화 상태, 전하, 입체화학, 염 형태를 임의로 바꾸지 않는다. 구조가 모호하거나 검증에 실패하면 추론에 들어가지 말고 누락 항목을 기록한다.

### 2. 예측 환경 점검 및 실행

저장소 루트에서 입력 식별과 실행 전 사전검사를 수행한다.

```powershell
py -3.13 -B -X utf8 scripts/prepare_target.py `
  --input inputs/<target_id>.json `
  --output validation/<target_id>-identity.json
py -3.13 -B -X utf8 scripts/preflight_models.py `
  --input inputs/<target_id>.json `
  --output validation/<target_id>-preflight.json
```

사전검사가 통과한 뒤에만 새로운 run ID로 실제 모델 파이프라인을 실행한다.

```powershell
py -3.13 -B -X utf8 scripts/run_pipeline.py `
  --input inputs/<target_id>.json `
  --run-id <target_id>-live-YYYYMMDD-01
```

실행 결과는 `results/<run_id>/`에 저장한다. 원시 요청·응답·로그·구조 그림·매니페스트·검증 기록을 보존한다. 기존 run을 덮어쓰지 않는다. 실행 불가, 모델 오류, 출력 파싱 실패, 범위 미확인은 정확한 상태와 사유를 남기고 Mock Data로 대체하지 않는다. 사전검사나 파일 생성이 `success`여도 화학적 정확성이나 실험 재현을 뜻하지 않는다.

### 3. 모델별 역할과 공식 출처

사용 가능한 모델과 그 한계를 보고서 및 재현 안내에 기재한다. 실행한 모델만 이번 물질의 예측 결과를 낸 것으로 서술한다.

| 작업 | 공식 저장소 | 보고서에서 구분할 점 |
|---|---|---|
| 역합성 경로 탐색 | [AiZynthFinder](https://github.com/MolecularAI/aizynthfinder) | 타깃 구조에서 전구체 분해 트리를 탐색한다. `solved`, 재고 표시, 점수는 실험 가능성·재고 최신성·수율을 입증하지 않는다. |
| 경로 탐색 대안 | [SynthEx](https://github.com/schwallergroup/synthex/tree/submission) | 이 저장소에 실행 어댑터와 검증된 결과가 없으면 `not_implemented` 또는 미실행으로 둔다. |
| 조건 추천 대안 | [ASKCOS v2 context recommender](https://gitlab.com/mlpds_mit/askcosv2/context_recommender) | 연결된 서비스·모델을 실제 실행하지 않았으면 결과를 만들지 않는다. |
| 반응 조건 추천 | [Parrot](https://github.com/wangxr0526/Parrot) | 촉매·용매·시약 슬롯은 모델 후보 출력이다. `catalyst1`, `solvent1`, `solvent2`, `reagent1`, `reagent2` 필드를 정확히 보존하고 화학적 역할 해석과 분리한다. |
| 반응 수율 추정 | [rxn_yields](https://github.com/rxn4chemistry/rxn_yields) | 실제 체크포인트·정규화 근거·적용 범위를 기록한다. 반응 구조만 입력했다면 조건별 실험 수율이 아니다. |
| 반응 지문 | [DRFP](https://github.com/reymond-group/drfp) | DRFP 자체는 수율 회귀 예측기가 아니다. 별도로 검증된 학습 회귀기와 메타데이터가 없는 한 산출율 모델로 취급하지 않는다. |

실행 전 모델 코드·체크포인트·토크나이저·설정·재고의 출처와 버전 또는 체크섬을 점검한다. 가중치와 대용량 재고는 저장소에 넣지 않는다. README와 `configs/model-assets.lock.json`의 설치·다운로드 절차 및 체크섬 기록을 따른다. 각 모델의 입력, 출력, 실제 실행 여부, 오류, 검증 범위를 보고서에 밝힌다.

### 4. 경로·조건·수율 결과 취합

원시 결과를 먼저 확인하고 `route_id`, `step_id`, 정확한 반응 SMILES로 경로·조건·수율을 연결한다. 다단계 경로는 중간체 순서와 각 단계의 반응물을 유지한다. 다른 경로·단계·후보 순위의 조건 토큰을 옮기거나 합치지 않는다.

전체 탐색 후보, 검토용 shortlist, 본문에 자세히 설명할 대표 경로를 구분한다. 개수와 선정 기준은 원시 결과에서 확인한다. 점수 순위, 단계 수, 직접 일치하는 문헌 선례 등 실제로 확인된 근거만 사용한다. 미확인 가격·실험 난이도·용이성을 덧붙이지 않는다. 문헌 조사가 추론 후 수행된 경우, 모델 입력·점수에 반영되지 않았음을 분명히 한다.

각 대표 경로의 반응 그림·출발물질·생성물·단계 번호·작용기 변화를 같은 route/step 번호로 연결한다. 보고서 표는 단계당 한 행으로 구성하고 조건과 수율을 같은 단계에 둔다. 조건 값이 없으면 `NOT SUPPLIED` 또는 “모델 출력 슬롯이 비어 있음”으로 표시한다. 빈 모델 슬롯을 실험에 해당 성분이 없었다는 뜻으로 해석하지 않는다. 조건 후보 점수는 수율·확률·실험 성공률이 아니다.

수율 모델의 입력이 반응 SMILES뿐이면 출력은 조건에 종속된 실험 수율이 아니라 모델 예측값이라고 표시한다. 정규화 방법, 체크포인트 해시, 통계량과 검증 여부를 함께 기록한다. 서로 다른 단계의 예측값을 곱해 검증된 전체 경로 수율로 만들지 않는다. 문헌 수율과 수치 비교를 할 때는 수율 정의·조건 차이·학습 자료 중복 미확인을 명시한다. 한 사례는 모델 전체 정확도나 해당 실험의 성공을 증명하지 않는다.

### 5. 실제 분석 증거 취합

분석은 실행 기록과 원시 결과가 있는 경우에만 보고한다. 준비 파일·계획·모의 결과·정적 관찰을 실제 계산이나 측정으로 바꾸어 쓰지 않는다.

- **MOPAC:** 실제 입력·출력, 버전, PM7 등 방법, 전하, 다중도, 시작 배좌, 최적화 수렴 여부, 원자 번호·단위·결합 길이·부분전하·생성열을 원본과 대조한다. 조성이나 전하가 다른 분자의 총에너지를 직접 비교해 안정성·반응성을 순위 매기지 않는다. 고립 분자 계산은 반응 메커니즘, 활성화 장벽, 반응 속도, 수율의 증거가 아니다. 진동수 분석이 없다면 국소 최소점으로 확정하지 않는다.
- **EPI Suite:** BP·MP의 모델 추정과 데이터베이스·문헌 참조값을 구분하고 단위·방법·구조·전하를 기록한다. 순물질 물성만으로 반응 혼합물의 석출·기화를 단정하지 않는다. 온도·압력·용매·농도·당량·염/수화 상태·용해도 자료가 없으면 반응 상태를 미확정으로 둔다.
- **Discovery Studio Visualizer:** 직접 관찰한 구조 파일·물질·배좌·원자 번호·거리/각도·버전·화면 캡처를 기록과 연결한다. 분자 내부 거리·각도는 서로 다른 반응물 간 접근 거리·공격각이 아니다. 방향별 정적 화면은 한 분자 구조에서의 정성적 노출·가림만 뒷받침한다. 임의 배치는 설명용으로 표시한다. 미수행 측정·화면 오류를 숨기지 않는다. 정적 구조로 장벽·속도·수율을 확정하지 않는다.
- **하네스 비교:** 실제 요청·저장 응답·하네스 프롬프트 차이를 대조한다. OpenCode·Pi 등 각 1회 결과는 사례 비교이지 일반 성능 우열 증거가 아니다. 저장 응답을 문서로 다시 만든 것은 새 모델 호출 비교가 아니다. 사실 일치, 인용, 요구사항, 가독성, 누락·과장을 중심으로 비교하고 토큰·시간·비용은 보조 정보로 둔다.

### 6. Solar Pro 4 보고서 작성

모델별로 무엇을 입력받아 무엇을 출력했는지, 이번 실행에서 확인한 점, 실패·누락·미검증 범위를 근거 파일에 연결한다. 아래 독자 흐름을 따르는 자연스러운 한국어 학술 본문을 작성한다.

1. 표적 물질의 구조와 선정 이유
2. 구조 확인, 모델·실행 설정 및 검증 범위
3. 전체 탐색 결과, shortlist, 대표 경로 선정 근거
4. 대표 경로별 분자 구조 변화와 단계별 조건·예측 수율
5. 모델의 한계·실패와 MOPAC·EPI Suite·Visualizer·하네스 비교 등 실제 추가 분석
6. 각 결과를 종합한 조건부 경로 검토 우선순위와 실험 전 확인 사항
7. 재현 방법, 참고문헌, 프로젝트 증거 목록과 필요한 부록

실험값, 반응 메커니즘, 전자 이동, 조건, 기작, 활성화 장벽, 성능 수치를 계산·문헌·관찰 근거 없이 만들지 않는다. 과학적 주장은 해당 근거 가까이에 인용한다. 모델 저장소는 방법·구현 설명을 뒷받침하고, 프로젝트 파일은 이번 실행 수치·상태를 뒷받침하도록 구분한다. 본문에서 인용하는 각 문헌 번호와 `[D#]`가 실제로 존재하고 해당 주장을 지지하는지 확인한다.

전문용어는 처음 나올 때 한국어와 영어를 짝지어 간단히 정의하고 이후 같은 표현을 일관되게 쓴다. 작성 지시문·체크리스트·TODO·placeholder·출처 없는 문구를 본문에 노출하지 않는다. SMILES, 괄호, 전하, 결합기호 및 원자 연결은 원시 데이터·표·그림 간 보존한다.

### 7. DOCX·PDF 변환 및 최종 검증

Solar 응답은 근거 검증을 통과한 뒤 저장한다. 인용, 물질명, SMILES, 숫자·단위, route/step 연결, 조건 슬롯, 분석 완료/미완료 상태를 원본 파일과 대조한다. 미통과 응답은 과학 본문에 병합하지 않는다. 본문 문체·해석 수정이 필요하면 사용자가 허용한 호출 범위 내에서 이 스킬의 규칙을 보완하고 Solar가 다시 작성하게 한다. 문서 변환 문제는 변환 코드에서 해결한다.

DOCX를 생성하고 PDF로 변환한다. 두 파일 각각 참고문헌·부록을 포함해 **20쪽 이하**인지 실제 페이지 수로 확인한다. PDF 전체 페이지를 렌더링하여 그림·표·SMILES·캡션의 잘림, 글씨 크기, 과도한 공백, 중복, 제목 고립, 지시문 노출을 점검한다. DOCX의 본문·그림·표가 검증된 Solar 응답과 일치하는지도 확인한다. 저장 응답에서 문서를 재생성한 범위와 새로운 물질 입력으로 모델 추론·Solar 작성을 재현한 범위를 구분해 기록한다.

재현 안내는 실제 명령, Python/프로그램 버전, 의존성 목록, 모델 공식 저장소·체크포인트 준비 방법, 필요한 환경변수의 이름과 설정 위치를 포함한다. API 키 값·사용자 인증정보·개인 PC 절대 경로는 공개하지 않는다. 재현되지 않은 절차는 안내 확인인지 실제 실행 검증인지 분리한다.

## 현재 실행 경로

- 입력 템플릿: `inputs/input-template.json`
- 입력 확인·구조 검증: `scripts/prepare_target.py`
- 모델 환경 사전검사: `scripts/preflight_models.py`
- route/condition/yield 예측: `scripts/run_pipeline.py`
- 추가 분석 증거 수집: 각 분석 도구의 기록 및 `scripts/prepare_additional_analyses.py`
- Solar 보고서 요청 준비·실행: `scripts/generate_report.py` 또는 최신 증거 번들 전용 `scripts/generate_solar_report_from_bundle.py`
- DOCX/PDF 변환: `scripts/export_report_docx.py`, `scripts/convert_docx_to_pdf.ps1`
- 근거·인용·문서 검증: `scripts/audit_citations.py` 및 해당 release validator
- 실행 설정과 기본 스킬 경로: `configs/report-plan.json` (`skill_path: skill/SKILL.md`)

새 분석이나 모델 호출을 시작하기 전에는 사용자의 요청 범위, 모델별 사전검사, 예산 및 승인 게이트를 확인한다. 기존 결과는 입력으로 재사용할 수 있지만 다른 물질의 결과로 대신하지 않는다.
