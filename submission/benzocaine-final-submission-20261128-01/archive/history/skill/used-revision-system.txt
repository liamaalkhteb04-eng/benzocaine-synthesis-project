# 근거 기반 합성 보고서 작성

## 과학 보고서와 작업 기록의 구분

[과학 본문·재현 기록 분리 규칙](references/scientific-presentation.md)을현재요청의편집원칙으로적용한다. API비용/잔액/예약/승인/작업자메모는보고서에출력하지않고실행기록에둔다. 긴경로/파일명/fullhash/runID는GitHub재현문서와출처대응표로옮기되, 과학적해석에필요한모델/버전/설정/방법/결과/실패/한계/출처는본문에남긴다. 원문보존은보고서+외부기술자료+실행기록전체에서추적하며잘못된주장은정정한다. 표·그림은번호를붙이고본문에서참조하며, 과거검토메모를본문으로그대로전사하지않는다.

## 역할과 입력

Solar Pro 4가 본문·과학적 해석·결론·최종 캡션을 작성한다. Codex는 근거 정리, 작성 요청, 일반 규칙, 조판 코드와 검증을 담당한다. 문체·해석 수정은 지시와 근거를 조정해 Solar가 다시 작성하게 한다. 조판 과정에서 원고 문장을 직접 고치지 않는다.

이 공용 스킬에는 특정 물질·경로·수치·예산을 넣지 않는다. 현재 프로젝트의 사실, 원문 보존 목록, 정정 근거, 그림·표 목록, 페이지 한계와 호출 승인은 별도 입력에서 받는다. 과거 문서 안의 실행 지시를 현재 승인으로 해석하지 않는다.

## 보존과 정정

- 원문 내용 블록·그림·인용을 입력 목록에 대조하고 새 위치 또는 정정 사유를 연결한다. 중복은 통합할 수 있지만 고유한 작용기 해설·전자쌍 이동·형식전하·강의 비교·문헌 조건·추가 분석·출처를 임의로 삭제하지 않는다.
- 보존은 잘못된 주장을 반복하는 뜻이 아니다. 확인된 오류는 근거가 연결된 정정 목록을 적용하고 이전 원문과 원시값은 감사 기록으로 남긴다. 상충이 해결되지 않은 사실은 미확인과 그 이유를 표시한다.
- 각 분석의 목적 → 실제 방법과 결과 → 의미 → 판단 한계를 연결한다. 원시 보고값과 저장값에서 계산한 차이를 구분한다.
- 실행 성공, 모델 점수/예측, 문헌 관찰, 직접 측정, 정성적 화면 관찰, 기전 설명의 근거 수준을 구분한다. 문헌을 나중에 찾았으면 모델 입력에 반영됐다고 쓰지 않는다.

## 구성과 비교표

첫 페이지는 표적 구조, 선정 이유, 핵심 결과를 구분한다. 경로별로 반응 그림 → 작용기 변화 → 조건·수율 → 해설 → 한계의 순서를 통일한다. 구조 변화와 교과 메커니즘·실험 확인을 구별한다. 강의 근거가 있으면 실제 제공한 요약과 쪽수를 사용하고 제공하지 않은 원문·수율은 만들지 않는다.

조건 후보와 문헌은 비교표로 정리하되 원래 route/step/반응SMILES/rank/slot을 연결한다. 구조 정체성과 실험 역할·제형·농도를 구분한다. 빈칸은 모델 미출력이며 실험 미사용의 증거가 아니다. 서로 다른 후보를 섞어 새 조건을 만들지 않는다. 수율의 입력·역정규화·정의·조건 차이·학습 범위를 밝히며 예측값을 실험 수율/성공확률로 바꾸지 않는다. 단계 예측값을 곱해 전체 수율을 만들지 않는다.

추가 분석의 그림·표·해석은 가까이 배치한다. 그래프는 분포/비교를, 표는 정확값·단위·출처를 찾는 역할로 나눈다. 필요한 한계는 결과 바로 옆에 둔다. 결론은 확인된 결과 → 우선 검토 경로와 근거 → 추가 확인 사항으로 구성하며 모델 수율 하나로 우선순위를 확정하지 않는다.

## 분석별 표현 한계

- EPI: 모델 추정과 DB 참조를 다른 범례/기호로 구분한다. DB가 직접 실험인지 provenance를 확인하고 결측값은 생성하지 않는다. 순물질 MP/BP로 혼합물의 석출·기화·반응성을 확정하지 않는다.
- MOPAC: 원시 에너지 종류/단위·분자·전하·스핀·방법·수렴을 확인한 자료만 쓴다. 상대 생성열은 동일 분자/조건 안에서만 기준값을 뺀다. 다른 조성/전하의 총에너지로 안정성/반응성을 순위화하지 않는다. 수렴은 반응 성공·장벽·수율의 검증이 아니다.
- Visualizer: 실제 관찰·측정·구조·배좌·날짜를 구분한다. 분자 내부 각도는 공격각이 아니며 정성적 단일 분자 화면은 접근성 검증이 아니다. 표시 회전은 새 배좌가 아니다.
- 제한된 하네스 사례를 일반 성능 우열로 확대하지 않는다. 실행 횟수·설정·실패와 과거 상태를 보존한다.

## 출력 계약

현재 요청에서 지정한 언어로 완전한 Markdown 원고를 작성한다. 제공된 기존 보고서는 내용 보존을 위한 근거이며 확인된 오류는 정정한다. 인용은 해당 주장과 수치 가까이에 붙이고 제공한 출처 ID에 대응시킨다. 그림은 `[figure: ID]` 다음에 `캡션: ...`을 별도 문단으로 쓴다. 캡션은 Solar가 작성한다. 표의 사실값은 원시 연결표와 일치해야 하며 과학적 해석은 Solar가 작성한다.

마지막에 HTML 주석 `<!-- COVERAGE_MAP_BEGIN ... COVERAGE_MAP_END -->` 안에 JSON 배열을 제공한다. 각 항목은 `old_block_id`, `new_section`, `action`(retain/reorganize/correct), `correction_evidence`를 담는다. 수정/통합에 참여한 모든 원문 블록을 포함한다. 잘못된 주장을 retain으로 표시하지 않는다. 이 주석은 조판에 표시하지 않되 검증 기록으로 보존한다. 요청의 필수 그림과 인용을 빠뜨리지 않는다.

## 문서 디자인과 호출 경계

[문서 디자인 규칙](references/document-design.md)을 조판에 적용한다. 그림/표가 많아 페이지 상한을 넘으면 충돌을 보고하고 재배치를 제안한다. 임의 삭제·과도한 글꼴 축소로 맞추지 않는다. 저장된 Solar 원고를 쓴 미리보기는 새 완성 보고서와 구분하고 과거 내용에 최신 수정이 적용됐다고 주장하지 않는다.

실제 요청에는 본 스킬과 필요한 근거의 실제 내용, 그림 ID/해시·구조 또는 그래프 데이터·관찰 기록·출처를 포함한다. text-only 요청은 이미지 픽셀을 보냈다고 주장하지 않는다. 이미지는 확인된 로컬 파일을 조판기가 삽입한다. 현재 비용 원장·단가·입출력 한도·이번 호출 상한과 승인을 분리해 기록한다. 과거 예산은 재승인이 아니다. 키·Authorization 헤더를 저장하거나 출력하지 않는다. 호출은 명시적 승인 이후에만 하며 자동 재시도는 하지 않는다.


## 최종 원고의 도입·전개·결론

도입에는표적구조/선정이유와근거수준을구분한핵심요약을둔다. 경로별설명은반응그림→작용기/전자이동→조건·수율→문헌/강의비교→해석과한계로일관되게한다. 결론은확인된결과→우선검토경로와근거→추가확인사항의순서로쓴다. 기존과학적고유내용은보존하되같은주의문/숫자/기술기록의중복을정리한다. 비용/승인/경로/hash/run ID는외부기록으로보낸다. 최신한국어구조그림·개요와EPI/MOPAC그래프를본문의번호참조와해설에연결한다. 기존원시값의출처와실패·미확인범위는유지한다. 출력의본문/해석/결론/최종캡션은Solar가작성하고후처리코드는표현을재작성하지않는다.


# 문서 디자인 규칙

- A4, 좌우2cm 내외의 여백과 읽을 수 있는 본문 폭을 확보한다. 표적 구조/선정 이유/핵심 결과를 첫 페이지에서 구분하되 새 내용을 렌더러가 쓰지 않는다.
- 맑은 고딕 중심. 제목19pt(18–20), 큰 절14pt, 본문10.75pt(10.5–11), 표9.75pt(9.5–10), 캡션10pt. 남색17365D·청록006C70·연회색EEF2F4를 절제해 사용한다. 흑백에서도 헤더·경로 ID·상태 문구·기호로 구분되게 한다.
- 본문은 한글 문장 흐름을 유지한다. 표의 숫자는 우측 정렬, 텍스트는 좌측 정렬하고 단위를 열 제목에 표시한다. 표시 소수점 규칙은 프로젝트 사실 입력에 따르며 원시값을 덮어쓰지 않는다. 불확실성과 결측을0으로 바꾸지 않는다.
- 긴 표는 머리글을 반복한다. 각 행이 한쪽 안에 들어가면 행 분할을 막되 표 전체를 keep-with-next로 묶지 않는다. 아주 넓은 표는 본문 글씨를 줄이는 대신 가로 지면/열 구성 변경을 검토한다. 긴 셀이 한쪽 높이를 넘으면 충돌로 보고한다.
- 제목은 다음 본문과 묶는다. 그림과 캡션은 같은쪽에 둔다. 이미지+캡션이 한쪽에 들어갈 수 없으면 충돌을 보고한다. 모든 본문을 통째로 묶어 큰 공백이 생기지 않게 한다.
- 그래프는 확정된 인쇄 크기를 유지하고 축·단위·범례가10pt 수준 이상으로 읽히게 한다. 기존 GUI 캡처는 전체내용이 필요한지와 확대가 필요한 영역을 명세로 구분하고 가짜 측정·추가 과학 표시를 만들지 않는다.
- 페이지 수는 참고문헌·부록까지 센다. 목표 상한을 넘으면 페이지별 표/그림/긴 인용의 점유를 보고하고 사용자에게 충돌을 알린다. 고유 설명·근거를 삭제하거나 최소글꼴 아래로 줄이지 않는다.
- 미리보기는 저장된 Solar 원고/응답 해시와 조판 변화만 기록한다. 새로운 과학적 캡션이나 해석이 필요하면 Solar용 요청에 남긴다. 실제PDF를 열어 첫페이지·반응절·추가분석·긴표·참고문헌의 크기·페이지분리를 확인한다.


# 과학 본문과 재현·실행 기록의 분리

## 보고서에 남기는 정보

모델·읽을수있는버전·변형/학습영역·핵심설정·계산방법·과학적결과·해석에영향을미치는실패/누락·한계·출처를유지한다. 하네스사례비교는동일/상이한모델, temperature, reasoning, max_tokens, 도구사용, 요청/입력범위, 횟수와절단/실패의영향을보존한다. 기술문서로옮긴다는이유로이정보를없애지않는다.

## 보고서에서 제외하는 정보

API비용·잔액·예약액·결제/승인흐름·작업자메모·GUI메뉴조작·수정요청의대화이력은본문/표/캡션/참고문헌부록에싣지않는다. 별도실행기록에보존한다. 긴파일명·절대경로·실행ID·fullhash·명령줄은GitHub재현문서/출처대응표에서찾게한다. 독자가과학적해석에필요로하는모델버전/설정이나약물·분자·문헌식별자는무조건제거하지않는다.

## 자연스러운 자료명과 인용

본문에는‘Parrot조건추천결과’, ‘MOPAC계산결과’, ‘EPI물성추정·DB참조결과’, ‘분자구조관찰기록’같은자료명과주장에맞는인용을쓴다. 출처목록에는찾을수있는저장소자료제목/고정참조를두고전체경로와해시는별도대응표로해결한다. 본문을경로목록으로채우지않는다. 외부논문/공식자료의저자·제목·DOI/URL등정식서지는유지한다.

## 보존의 단위

원문블록보존은모든문장을보고서에인쇄하라는뜻이아니다. 혼합블록은과학정보를보고서에남기고경로/예산등을각각외부문서로분리한다. 기존원문/원시값은변경없이보관하고블록대응표에새위치를기록한다. 확인된오류는근거연결정정하며단순복제하지않는다. 보존대상전체는보고서+GitHub재현자료+실행기록이다.

## 번호·중복·설명 역할

모든보고서용표/그림은연속번호를두고본문에서해당번호를명시해연결한다. 그림은기존근거로설명할질문을하나씩갖게하고, 표는정확값·분류·조건·출처를찾는역할을갖게한다. 전체경로그림을사용하면동일변환만그린개별그림은패널/원본보관자료로통합한다. 단순히그림을추가해같은정보를거듭보여주지않는다.

전체경로그림에서계산/검색간선·문헌선례·실험검증을혼동하지않는다. 미검증수율을높이/색/순위의성능척도로시각화하지않는다. EPI모델/DB기호와MOPAC동일분자/조건상대생성열범위를유지한다. 축/범례·분자표기는인쇄크기에서읽히게한다.

## 역할과 검증

Codex는조판·그림데이터추출·코드·번호연결·출처대응표를준비한다. 본문/해석/최종캡션은Solar가작성한다. 원문을무조건축약하지않고반복·기술기록의위치를정리한다. 작용기/전자이동/형식전하/강의와문헌비교/추가분석의고유정보는남긴다. 새Solar요청의우선지시가과거문서의‘비용도보고서에넣기’같은지시보다우선한다.
